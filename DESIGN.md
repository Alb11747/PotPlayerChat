# Chat Deck interface

PotPlayerChat is a Windows companion for reading recorded Twitch chat beside PotPlayer. The transcript is the primary surface; playback synchronization, instance recovery, and virtualized message rendering remain independent of the appearance layer.

## Approved appearance

Streamlined combines instance tabs and actions in one toolbar, with a compact status strip below the toolbar only while reading earlier messages. The strip shows Return to playback and the current playback time; clicking the time exposes offset adjustment. The recording title appears only in its tab. Recording tabs share its remaining width; Main and actions keep their compact size. Comfort separates the controls and adds spacing between messages. Both layouts use 17.5px chat text, 14.5px timestamps, 24px badges, and 40px emotes at the default 16px root, expressed in rem to scale together. Badges and cheers use centered inline alignment, with cheer amounts centered beside their icons; regular emote bottoms align with the normal text baseline. Both keep 2px gaps, and these proportions also apply to Search and profile transcripts. Both layouts hide the status strip while following playback. Inline preview images are centered within the message width. Graphite, Blue, and Lavender are independent palette choices. The default is Streamlined with Blue. Use Segoe UI, restrained separators, compact controls with four-pixel corners, and visible keyboard focus. Native windows retain their normal frames.

Shared CSS tokens live in the renderer's base stylesheet. Layout and palette are applied to the document root; message components use density tokens rather than fixed dimensions. All screens must remain usable at 360, 420, and 600 pixels wide. Settings, Search, and profile headers stay compact while their contents scroll. The profile message count sits immediately beside its history label.

## Settings and cross-window behavior

The existing configuration store persists `interface.layout`, `interface.palette`, and `interface.previewMode`. Existing unrelated preferences and per-video offsets survive migration. Defaults are cloned before hydration and reset. Saving is disabled until hydration completes; appearance notifications update open renderers without writing the notification back to storage.

Settings categories are Appearance, Chat, Previews, Search, Advanced, and Maintenance. They preserve the existing fields and units. Changes save immediately; app-cache clearing and seen/clicked-URL clearing remain separate operations.

Improve username contrast is enabled by default under Appearance and updates all open windows. Sender names, mentions, action text, and profile names keep their exact source color when it has at least 3:1 contrast on the normal chat and profile-header backgrounds. Hover and first-message highlights do not trigger recoloring of these already visible names. Only colors below that visibility threshold are brightened toward 4.5:1 across the active palette's normal, hovered, and first-message backgrounds. The renderer caches corrections without changing stored Twitch colors; disabling the preference restores the source colors.

## Navigation and previews

Normal username activation opens the profile; Alt activation searches the bare username. Search and profile windows carry their source recording and message context. Returning to a historical message does not seek PotPlayer: chat displays that history until Return to playback is activated.

Original hover is the default preview mode. It follows the pointer, honors placement and sticky preferences, and contains no action or close buttons. Larger on click opens independent, non-modal native preview windows; Control activation opens them in either mode when previews are enabled. Inline-image click preferences remain separate.

Preview windows use the same one-time popup context registry as Search and profiles. Only exact packaged or development renderer routes are allowed; lifetime belongs to the source window. Closing a preview restores its trigger focus when the trigger still exists.

Expanded links provide Open link, Copy link, and SauceNAO. Copy retains the original URL. SauceNAO encodes the HTTP(S) thumbnail URL and is disabled without one. Retry refreshes only that URL's metadata/cache entry. Tooltip markup continues through the existing sanitizer.

## Transcript layout and scrolling

Main chat, Search, and profile history share a virtual transcript. Pretext prepares text once and estimates mixed text/media row heights; native DOM measurements remain authoritative for wrapping, selection, and interactions. Rows are keyed by message identity, with one viewport of overscan on each side. Prepared text and decoded media dimensions survive row recycling.

Unknown rows initially reserve 48px. Pretext refinement prioritizes the viewport and navigation target, then works through history in batches of at most 64 messages or 4ms, yielding after paint between batches. Published batches update only their changed rows. Asset notifications invalidate dependent messages or channels; data and layout changes cancel obsolete work. Estimates must not synchronously parse the full history or displace a valid DOM measurement.

Initial mounting renders the viewport before adding overscan after a paint. Large dataset replacement prepares dependency indexes, estimator state, and geometry cooperatively; rows and their presentation context publish together. Height updates copy only affected paths in an immutable sum tree with compact blocks of heights. Saved anchors retain their original geometry, so a replacement that removes the reading message re-seats its nearest surviving neighbour. Navigation queues by message identity while replacement is pending, and user input cancels it.

Search receives original message references through the opener context. Source-owned weak caches share ordered snapshots and lazy searchable text across popups; result arrays refer to those same objects. Queries also match the plain details text of link previews already loaded by the main window or a Search popup, looked up by URL at match time; search never requests previews. Merging, filtering, and complete color-timeline reconstruction yield in four-millisecond batches. The previous results keep their matching highlight pattern and colors until replacement rows are ready. Each popup retains its captured recording and its own loading and UI state; history requests are still local to that popup.

Search opens with a focused native input in its initial HTML. The lightweight entry consumes its popup context before loading the transcript and service modules. The full interface binds that same input without moving it, preserving early edits, selection, focus, and native undo history; active text composition finishes before binding. Loading failure leaves the query editable with an error message.

Search first renders a bounded neighborhood of up to 200 messages around its opening target. Ready badges, emotes, and captured mention colors accompany those original message references; missing assets never delay readable chat. With an empty query, scrolling within one viewport of either end adds up to 200 older or newer messages while retaining the reading anchor. Captured messages are reused; missing history is requested in five-minute intervals without full-day backfill. The header reports messages loaded, with directional loading and retry states. A nonempty query starts full-history preparation after the preview has a paint opportunity and retains complete filtering and result counts. Clearing the query returns to a bounded neighborhood around the first visible result, or the opening target when there are no results. Case and regex options alone do not load full history.

Inline previews appear once thumbnail metadata is available and use a text-sized image while decoding, then their natural bounded size. Unresolved emotes use the larger of the default 2.5rem square and their temporary text size; badge IDs reserve their boxes before metadata arrives. Loaded media compacts to its actual bounded size. Cheers scale to the full emote height even when their decoded asset is smaller, preserving aspect ratio and the 9rem width cap. Media callbacks must update asset state without issuing scroll commands.

The browser owns the reading position. Rows sit in normal flow between two spacers and Chromium's scroll anchoring keeps the reader's place when anything above it changes size, including during native smooth scrolling and scrollbar drags; the transcript does not rewrite the scroll offset to correct layout. Each row is one anchor candidate, and the anchor is the first message that starts on screen, so a message crossing the top edge can resize (media loading as it scrolls into view, text rewrapping on a width change) without moving what is below it. The transcript writes the offset only to pin the bottom while following playback, to hold an explicit jump on its message until the next wheel, pointer or keyboard input, and to re-seat the reading message once after the dataset is replaced. Those positions are always taken from mounted rows, never from estimates. Any upward movement leaves follow mode, whatever produced it; arriving at the bottom by user input offers follow mode to the owner.

Chromium suppresses anchoring for a whole layout pass when any element in the scroller enters or leaves normal flow (a change of `position` to or from absolute or fixed) and when a layout-affecting property changes on the anchor row or the scroller itself. Message content must not toggle `position` after mounting; create the element in its final flow instead. As a backstop, a shift that left the scroll offset untouched is corrected before paint. The mounted range uses hysteresis and spacer heights are whole device pixels, so subpixel differences between geometry and layout cannot flip the range or shimmer text under display scaling.

## Verification and delivery

Keep regression coverage focused on settings migration/reset, cross-window notifications, popup ownership, activation modifiers, URL actions, and targeted retry. Inspect real components across the supported palette/layout/width combinations, including empty/error states and focus. Verify the actual unpacked executable with isolated test settings and distinguish fixture-backed UI checks from live PotPlayer/service integration.

Standalone mock galleries remain outside this repository. Their sample messages, simulated controls, and comparison navigation are not application features.
